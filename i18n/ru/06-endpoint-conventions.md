# 06. Соглашения для конечных устройств

> Перевод носит информативный характер; нормативный текст: [английский](../../06-endpoint-conventions.md).

Как называть рабочие устройства сотрудников (ноутбуки и настольные компьютеры), какие у них метки и почему их нет в DNS сервисов. Типовая архитектура для этих устройств: [blueprint endpoint](https://github.com/mess-systems/blueprints/tree/main/endpoint).

## 1. Зачем отдельное семейство

Форма **Хост / контейнер / ВМ** из [раздела 5 в 01](01-naming-conventions.md) (`<site>-<plane>-<domain>-<product>-<env>-<NN>`) описывает развёрнутую инфраструктуру сервисов. У ноутбука нет настоящих значений `site`, `domain`, `product` и `env`: устройство перемещается, на нём много продуктов, и оно не окружение развёртывания. Если втиснуть его в эту форму, придётся выдумывать значения и потом переименовывать.

Это новое **семейство** объектов, а не новая DNS-грамматика: правило «грамматики C нет» остаётся в силе.

## 2. Форма

```
<profile>-<form>-<asset-id>          # std-lt-a1b2c3, eng-dt-d4e5f6, paw-lt-g7h8j9
```

| Ось | Код | Значение |
|---|---|---|
| `profile` | `std` | Стандартное устройство сотрудника (базовая конфигурация по умолчанию) |
| | `eng` | Инженерное устройство с действительно отдельной базовой конфигурацией: сборка, AI-агенты для кода, песочницы, другая телеметрия. Установленной IDE для этого недостаточно. |
| | `paw` | Выделенная защищённая рабочая станция для привилегированного доступа, только для администрирования |
| `form` | `lt` | Ноутбук |
| | `dt` | Настольный компьютер или стационарная рабочая станция |
| `asset-id` | 6 символов | Выдаёт учётная система активов; не меняется за всё время жизни устройства |

- **Не `dev`.** `dev` уже код окружения ([раздел 4.4 в 01](01-naming-conventions.md)); у кода не бывает второго значения.
- **Алфавит `asset-id`:** `a-z 2-9` без `o`, `l`, `i`, так исключены неоднозначные символы `0 o 1 l i`. Первый символ обязательно буква. Существующий инвентарный номер можно использовать, если он соответствует этим правилам. Серийный номер использовать запрещено: он раскрывает производителя и не является непрозрачным.
- Regex: `^(std|eng|paw)-(lt|dt)-[a-hjkmnp-z][a-hjkmnp-z2-9]{5}$`. Псевдоним BYOD: `^byod-(lt|dt)-[a-hjkmnp-z][a-hjkmnp-z2-9]{5}$`.

## 3. Длина

Имя `std-lt-a1b2c3` состоит из **13** символов, псевдоним BYOD из **14**. Жёсткий предел 15 символов: это ограничение [шаблона имени Windows Autopilot](https://learn.microsoft.com/en-us/autopilot/profiles) и [имени NetBIOS](https://learn.microsoft.com/en-us/troubleshoot/windows-server/active-directory/naming-conventions-for-computer-domain-site-ou). [Переименование в Intune](https://learn.microsoft.com/en-us/intune/device-management/actions/rename) допускает для Windows до 63 символов (проверено 2026-10-12), но не для гибридно присоединённых устройств. Запас 2 символа: новый код профиля должен оставаться из 3 букв, код формы из 2.

## 4. Чего никогда нет в имени

Площадки, окружения, домена, продукта, логина пользователя, отдела, ОС, модели, серийного номера, состояния соответствия и уровня привилегий. **Имя никогда не даёт доступа.**

## 5. Метаданные

Ключи: `plane`, `owner`, `tier`, `data_class`, `exposure`, а также `ownership` (`org`, `personal`, `partner`), `endpoint_profile`, `device_form`, `asset_id`, `assigned_to` (субъект IdP, в имени никогда), `management` (`full`, `work-profile`, `registered`) и `compliance_state` (из системы управления устройствами, в имени никогда). `capability` всегда `endpoint`. Как метки и теги эти ключи пишутся через дефис по [05](05-labels-and-tags.md) (`endpoint-profile`, `device-form`). Запись идентифицируется ID устройства в системе управления или каталоге, а не именем хоста. Полная таблица в [английском тексте](../../06-endpoint-conventions.md#5-metadata).

**Профиль и плоскость.** Профиль выбирает базовую конфигурацию, плоскость выбирает зону доверия. Устройство `eng` обычно имеет `plane=eng`, `std` и `paw` обычно `corp` или `shared`. Каталог обязан проверять это сочетание.

## 6. Код возможности `endpoint`

`endpoint` это [код возможности](01-naming-conventions.md) для всего, что работает на устройстве сотрудника: агенты управления устройствами, агенты безопасности и доступа, удалённая поддержка, контроль AI-клиентов, локальные среды контейнеров. Он используется в каталогах, техрадаре и тегах затрат. В имени устройства и в DNS сервисов он не появляется.

`endpoint` входит в домен `device` (устройства сотрудников; не сетевое оборудование и не IoT). Техрадар и каталог ПО используют тот же код как категорию, так что словарь один. Серверное виртуальное рабочее место (рабочие столы в браузере) это возможность `vdi` в том же домене, с обычным именем сервиса. Домен никогда не входит в имя устройства.

## 7. DNS и регистрация

- В зоне сервисов (`*.svc.mess.systems`) для устройств нет статических записей. Имя вида `std-lt-a1b2c3.corp.mess.systems` это «грамматика C», и оно отклоняется. Имя может появляться в динамическом DNS или mDNS локального сегмента.
- Имя регистрируется в каталоге **до** подключения устройства.

## 8. BYOD

У личного устройства остаётся собственное имя; корпоративного имени, записи DNS и узловой идентичности SPIFFE у него нет. Система управления может присвоить псевдоним `byod-<form>-<asset-id>`, только для учёта и аудита. Политика определяется достоверными атрибутами: владением, режимом подключения, аттестацией, издателем сертификата и соответствием, но не псевдонимом.

## 9. PAW: класс устройства, а не уровень привилегий

Запрет на уровень привилегий в имени (`admin.`, `t0-`) остаётся в силе. `paw` разрешён, потому что обозначает класс устройства со своей защищённой базовой конфигурацией. Если для каждого уровня есть своё железо, имя хоста всё равно `paw-<form>-<asset-id>`, а уровень хранится только в ключе `tier` и в имени профиля, например `paw-t0`. По имени видно, что это PAW; какой уровень с него администрируют, смотрят в каталоге. Обычный ноутбук администратора не получает имя `paw`.

## 10. SPIFFE

Полностью управляемое устройство, прошедшее аттестацию, может получить узловой ID `spiffe://mess.systems/node/<имя-устройства>`, например `spiffe://mess.systems/node/std-lt-a1b2c3` ([раздел 8 в 04](04-identity-conventions.md)). Никогда не логин пользователя. У BYOD узловой идентичности нет.
