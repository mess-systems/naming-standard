# 参与贡献

感谢您帮助改进本命名标准。本标准欢迎争论：来自不同公司、使用不同技术栈的同行会带来让它失效的案例。

## 在哪里讨论

| 您有…… | 使用 |
|---|---|
| 问题、边界情况、“X 应该怎么命名？” | GitHub **Discussions**（Q&A 或 Ideas） |
| 具体变更：新代码、规则修改、错误示例、失效链接 | 使用 *Proposal* 模板提交 **Issue**，然后提交 pull request |
| 拼写错误或明显失效的链接 | 直接提交 pull request |

## 如何提出变更

1. **先搜索。** 代码必须在所有域中唯一（见[能力代码](01-naming-conventions.md#43-能力代码在所有域中唯一)）；请检查各表格和已有的 issue。
2. **用示例说明问题**，而不只是给出您想要的规则。请使用虚构名称（`example.com`、`*.example`、`corp.lan`、`jdoe`、`acmecloud`）。
3. **说明会破坏什么。** 哪些文件和章节会改变？是否会使现有的合法名称变为不合法（破坏性变更），或使不合法的名称变为合法（增量变更）？
4. **保持语法封闭。** “我们需要一个特例”通常意味着缺少一个代码或一个组，而不是需要新的语法（见[不存在语法 C](01-naming-conventions.md#33-不存在语法-c)）。
5. **提交 PR**，在一次变更中更新所有受影响的文件：规则、表格、编码示例、拒绝规则，以及必要时的[完整示例](02-worked-example.md)。

编辑规则：英文、Markdown，尽可能一条规则一句话，用表格表示映射关系。引用其他文件和章节时使用相对链接，链接文字写明目标内容，例如 `[capability codes](01-naming-conventions.md#43-capability-codes-unique-across-all-domains)`；不要只写章节编号或章节符号。外部标准（RFC、NIST 控制项）在首次提及时链接到其权威来源。

## 讨论规则

- 具体且友善。批评名称和规则，而不是个人或雇主。
- 以约束条件（RFC、产品限制、审计与安全要求）以及用虚构术语描述的真实案例作为论据。
- 每个主题一个讨论串。相关讨论串之间用链接关联，而不是合并。
- 有分歧是正常的；由维护者做出决定，并在 issue 或变更日志中记录理由。
- 不要分享任何对您的雇主或客户而言属于机密的内容。

## 发布前检查清单（适用于每个 issue、讨论、PR 和示例）

发布前，请确认文本中**不包含**以下任何内容：

- [ ] 真实的内部主机名、域名或区域（您自己的或任何其他人的）——请使用 `example.com`、`*.example`、`corp.lan`。
- [ ] 真实网络的 IP 地址、CIDR、端口或 VPN/网状网络细节。如需示例地址，请使用 [RFC 5737](https://www.rfc-editor.org/rfc/rfc5737)（`192.0.2.0/24`）或 [RFC 3849](https://www.rfc-editor.org/rfc/rfc3849) 中的文档地址段。
- [ ] 机密或任何看起来像机密的内容：令牌、API 密钥、密码、私钥、连接字符串、真实的机密路径。
- [ ] 人员或系统的真实用户名、账号 ID、组名或电子邮件地址。
- [ ] 真实组织的容器/虚拟机 ID、资产标签、工单编号或内部决策记录 ID。
- [ ] 尚未公开的客户、雇主或供应商合同细节。
- [ ] 显示上述任何内容的截图。

维护者会编辑或删除未通过此检查清单的内容。如果您不慎发布了敏感内容，请先轮换相关凭据，然后请维护者将其彻底清除。

## 翻译

仓库根目录下的英文文件为规范性文本。`i18n/<lang>/` 中的译文和 `README.<lang>.md` 仅供参考；如有任何不一致，以英文文本为准。

- 先修改英文文本。译文可以滞后于英文，但绝不能增加英文中没有的内容或与之矛盾。
- 更新译文时，请翻译有变化的章节，并在译文开头的说明中把源提交更新为当前所对应的英文提交（`git log -1 --format=%h -- <file>`）。
- 只翻译说明性文字。绝不翻译名称、令牌、代码、FQDN、路径、表格中的标识符列或代码块。保留标题编号和 Markdown 结构；链接文字需要翻译，锚点指向同目录译文中对应的翻译标题。
- 译文中的相对链接指向同目录下的译文（`03-secrets-conventions.md`），指向根目录文件时使用 `../../`（`../../LICENSE`）。
- 新增语言时，添加使用 [BCP 47](https://www.rfc-editor.org/info/bcp47) 标签命名的 `i18n/<lang>/` 目录（`ru`、`zh-CN`）、一个 `README.<lang>.md`，并在每个语言切换栏中加入该语言。
